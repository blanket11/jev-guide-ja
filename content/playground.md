:::brief 質問を固定し、文章だけ変えて比べる
- **材料：** 機能追加を求める短い文章をStateへ入れます。
- **質問：** まずはNoulを1問だけ作ります。
- **比較：** 明確な要望・操作の質問・曖昧な文章を順に試します。
:::

:::flow 最初の実験の手順
Stateを入れる | 架空の問い合わせを用意
Noulで聞く | 「機能追加を求めている？」
値を比べる | 質問は同じまま文章を変更
! 期待する数値と、画面で実際に返った数値は区別して記録します。
:::

## Playgroundは、ブラウザー上の実験場
- Playgroundは、コードを書かずにJevへ材料と質問を渡せる公式の画面です。
- [公式Quick start](https://docs.typesafe.ai/introduction/quickstart)からPlaygroundを開き、ログインします。
- 画面の配置や利用可能な機能は更新される可能性があるため、このガイドでは固定のボタン位置に依存せず説明します。

利用権限がまだ付いていない場合は、サイト内の[リクエスト作成デモ](request-builder.html)でJSONの構造を学べます。こちらは本物のJevを実行するものではありません。

## まずStateに入れる文章
次の短い文章を使います。これは、このガイド独自の練習データです。

```text
予定をまとめて登録できる機能を追加してほしいです。
```

Stateは「何を判断するかの材料」です。この欄に長い依頼文を詰め込む必要はありません。質問は別の欄で設定します。

## 質問を1つだけ追加する
- 質問の種類はNoulにし、「この文章は、新しい機能の追加を求めていますか？」と指定します。
- JSON入力欄を使う場合の質問定義は次のとおりです。
- これは**質問部分だけ**であり、APIリクエスト全体ではありません。

```json
{
  "requests_feature": {
    "type": "noul",
    "instructions": "この文章は、新しい機能の追加を求めていますか？"
  }
}
```

Noulは、はいと判断する確率を0〜1で返します。この文章では1に近い結果を期待する、というのが教材の設定です。実際の値は、手元の画面で確認してください。[公式：Noul](https://docs.typesafe.ai/primitives/noul)

## 今度は、文章だけを変える
- 「予定の登録方法を教えてください」に置き換えます。
- 機能の追加ではなく使い方の質問なので、最初の文章より低い値を期待します。
- 続いて「まとめて登録できないのですが、どうすればよいですか」も試します。
- こちらは機能の有無や状況が曖昧です。

大切なのは、まず**質問を固定して入力だけを変えること**です。両方を一度に変えると、結果が変わった理由を切り分けにくくなります。

## 記録する内容
実行に使った文章、質問文、モデル名、返ってきた数値、自分の期待と合ったかを残します。最初から何百件も集める必要はありません。まず明確な例と曖昧な例の違いが見えるようにします。

:::warning 数値は「機能追加の強さ」ではありません
Noulの0.8は、要望の熱量が80点という意味ではありません。「機能追加を求めている」という命題を、どれくらい肯定するかの確率です。
:::

:::answer 確認問題：結果が期待と違ったら、最初に何を見直しますか？
質問が本当に聞きたい条件になっているか、判断に必要な情報がStateにあるかを確認します。期待値自体が曖昧なら、先に分類の方針を決めます。
:::
