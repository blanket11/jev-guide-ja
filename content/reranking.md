## まず候補を探し、次に順番を見直す
FAQが増えると、キーワード検索だけでは、似た言葉があるだけのページが上に出ることがあります。そこで、まず検索で少数の候補を集め、その候補が質問に答えているかを評価し、順番を見直す方法を考えます。これが再ランキングです。公式にも、この2段階の構成を扱う教材があります。[公式：Re-ranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe)

Jevが自動的に自分のサイト全体を巡回してくれるわけではありません。候補の取得、閲覧権限による絞り込み、候補本文の取り出しは、こちらで用意します。

## FAQを題材にした設計例
検索文を「過去の予定をまとめて消したい」、候補を「予定を1件削除する」「予定を一括削除する」「予定を登録する」の3つとします。これらは架空の教材です。

```json
{
  "query": "過去の予定をまとめて消したい",
  "candidates": [
    { "id": "a", "text": "予定を1件選択して削除する手順" },
    { "id": "b", "text": "複数の予定を選択して一括削除する手順" },
    { "id": "c", "text": "新しい予定を登録する手順" }
  ]
}
```

このStateに対して、候補ごとに「`candidates[0].text`は`query`への直接の回答を含みますか」のようなNoulを作る設計が考えられます。候補が少なく入力上限に収まる場合は、独立した質問をまとめる方法も使えます。これは公式の再ランキングと並列質問の考え方を組み合わせた本ガイド独自の設計案です。[公式：Speculative fan-out](https://docs.typesafe.ai/patterns/fan-out)

## 上位1件を必ず表示しない
どの候補も無関係でも、数値で並べれば1位はできます。全て低い場合は「該当するヘルプが見つからない」という経路を残します。候補内の1位であることと、質問に答えられることは別です。

## 「Jevを入れたので検索が改善した」を測る
本ガイドの評価案では、典型的な検索文と正しいFAQの組を用意し、追加前後で正しいFAQが上位に入る割合、待ち時間、コストを比較します。元の検索が十分正確なら、再ランキングを入れない結論もあります。

候補を取りこぼしている場合は、並べ替えだけでは直せません。最初の検索で正しいFAQを候補に含める必要があります。

:::answer 確認問題：全文をJevに渡せば、検索基盤の代わりになりますか？
少量のテキストで意味検索を構成する例はありますが、規模・入力上限・更新・アクセス制御を無視した代替にはできません。まず候補を絞り、Jevに何を評価させるかを明確にします。
:::
