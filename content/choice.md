:::brief Choiceは、候補から「1つ」を選ぶ
- **choice：** 最も確率の高い選択肢です。
- **probabilities：** 全候補への確率の配分で、合計は1です。
- **注意：** 複数の独立したタグを返す仕組みではありません。
:::

:::cards この教材での、似ている分類の違い
bug | 試した操作の失敗・エラー
other | 内容は分かるが、分類の対象外
unclear | 主な用件を決める材料が不足
! 全選択肢は本文のJSONにあります。other・unclearは、この教材独自の分類方針です。
:::

## 1つのカテゴリを返してほしいとき
- Choiceは、用意した選択肢から1つを選びます。
- 返答の`choice`は最も確率の高い選択肢で、`probabilities`には全選択肢の確率が入ります。
- 分布の合計は1です。
- 別途`confidence`も返ります。 [公式：Choice](https://docs.typesafe.ai/primitives/choice)

## 問い合わせを分類する質問
次のコードは質問定義だけです。実際に送るときは`state`・`model`・`questions`を含むリクエストの中に置きます。

```json
{
  "type": "choice",
  "instructions": "問い合わせの主な用件を1つ選んでください。",
  "criteria": {
    "bug": "実行した操作が期待どおりに動かない、またはエラーになる報告",
    "feature_request": "現在はない機能の追加や改善を求める要望",
    "how_to": "機能の操作方法や設定方法を知りたい質問",
    "other": "用件は理解できるが、上記には当てはまらない",
    "unclear": "主な用件を決めるための情報が足りない"
  }
}
```

`bug`などのキーは、後でコードから扱う値です。キーと説明はモデルに送られるため、分かりやすく、互いの違いが明確になるようにします。質問全体の識別IDとは役割が違います。[公式：Choice](https://docs.typesafe.ai/primitives/choice)

## otherとunclearは違う
- 「いつも便利に使っています」という感謝だけの文章は、内容は理解できますが今回の分類の対象外です。
- 一方、「うまくいきません」だけでは、何をして何が起きたかが不足しています。
- この教材では前者を`other`、後者を`unclear`として扱います。
- これは公式の必須カテゴリではなく、このガイドの分類方針です。

## 選ばれた値だけでは分からないこと
- 仮に`bug`の確率が0.52、`how_to`が0.46で、残りが0.02だったとします。
- `bug`は最大でも、圧倒的に明確とはいえません。
- 逆に`bug`にほぼ全ての確率が集まるケースとは扱いを変えられます。
- これらは説明用の架空の確率で、実測値ではありません。

`confidence`は確率分布を要約した指標です。最大確率そのものと同じと決めつけず、[確率とconfidence](confidence.html)で読み方を確認してください。

## 境界が曖昧なら、説明に条件を足す
- 「削除できません。やり方を教えてください」は、質問形式でも不具合を訴えている可能性があります。
- 「不具合の具体的な症状が書かれていればbugを優先する」など、運営上どう分類したいかを先に決めます。
- ルールを決めずに「AIが正しく分けるはず」と考えると、結果を評価できません。

:::answer 確認問題：Choiceの5つの確率を、5つの独立したタグの有無として使ってよいですか？
その解釈は避けます。Choiceは候補間で1つを選ぶ分布です。独立して複数成立する条件は、別々のNoulで聞くなど質問の設計を変えます。
:::
