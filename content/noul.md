## Noulはtrueかfalseではなく、確率を返す
「この文章は機能の追加を求めていますか？」と聞いたとき、Noulが返すのは`true`そのものではなく、はいと判断する確率です。0に近ければいいえ側、1に近ければはい側です。Noulには独立した`confidence`フィールドはありません。[公式：Noul](https://docs.typesafe.ai/primitives/noul)

```json
{
  "type": "noul",
  "instructions": "この文章は、新しい機能の追加を求めていますか？",
  "criteria": {
    "true": "現在はない機能の追加を明示的に求めている",
    "false": "機能の追加を求めていない。操作の質問だけの場合も含む"
  }
}
```

`criteria`は省略できます。ただし「不満が書いてあるだけで要望とみなすのか」といった境界があるなら、はい・いいえの意味を具体的に書きます。[公式：Noul](https://docs.typesafe.ai/primitives/noul)

## 0.5を境に必ず自動化する必要はない
0.51ではい、0.49でいいえとしても、境界付近の判断は似ています。この教材では0.2以下をいいえ、0.8以上をはい、その間を確認対象に分けます。**この値は説明用であり、推奨の本番設定ではありません。** 正しい境界は用途と検証データによって決めます。

:::demo noul

## 返ってきた値をコードで使う
次のコードは、上のデモと同じ、教材用の分岐です。中間値を無理に真偽値にせず、`review`という状態で残します。

```js
function decide(probability) {
  if (probability <= 0.2) return "no";
  if (probability >= 0.8) return "yes";
  return "review";
}
```

「確認対象が多すぎるから」という理由だけで範囲を狭めると、自動処理の誤りが増える可能性があります。実測した誤りと確認の手間の両方を見て決めます。公式の自己一貫性の教材も、不確かな値の確認への振り分けを扱っています。[公式：Self-consistency: nouls](https://docs.typesafe.ai/cookbooks/consistency_noul_cookbook)

## 確率と程度を混同しない
「集中に向く音楽か」という質問の0.9は、集中力が90%上がるという意味ではありません。質問で定義した条件に対する肯定の確率です。効果の測定には、別の評価が必要です。

:::answer 確認問題：noulが0.1なら、モデルの自信が低いという意味ですか？
いいえ。はいの確率が低く、いいえ側に寄っているということです。0.5付近の方が、はいといいえが拮抗しています。
:::
