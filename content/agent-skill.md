## AIにコードを書かせる前に、仕様を渡す
TypeSafeは、APIの質問形式や設計パターンをコーディングエージェントへ伝える公式スキルを案内しています。Codexなどの環境でも利用するための手順があります。[公式：Agent skill](https://docs.typesafe.ai/agent-skill)

このガイドに載せるコマンドは、読者が自分の開発環境で実行するものです。この教材サイトを開いただけで、何かをインストールすることはありません。

## 公式が案内する導入方法
Claude Code以外のエージェント向けには、確認時点で次のコマンドが案内されています。

```bash
npx skills add typesafe-ai/skills --skill typesafe-ai
```

- 対話画面で利用するエージェントを選択します。
- 公式によれば既定はプロジェクト単位で、グローバルには`-g`を付けます。
- 同じスキルを複数の方法で重複して入れることは避けます。
- 実行前に公式の最新手順とスキルの内容を確認してください。 [公式：Agent skill](https://docs.typesafe.ai/agent-skill)

## 「Jevを入れて」だけでは設計が足りない
本ガイド独自の依頼例です。最初からサービスの主要機能を置き換えず、モックとテストを含めて依頼します。

```text
TypeSafeの公式スキルと最新ドキュメントを参照してください。

目的は、問い合わせに運営者向けの候補ラベルを付ける検証です。
既存の保存・公開・認可の仕様は変えないでください。

Jevの呼び出しはサーバー側またはローカル実行に限定します。
APIキーをブラウザー・生成物・ログに出さないでください。
最初は架空の日本語データとモックで実装してください。

質問は1つのChoiceから開始し、otherとunclearを区別します。
しきい値は仮定として明記し、実測の推奨値と呼ばないでください。
通信エラーと、分類不明の状態を分けてください。

成功・認証失敗・レート制限・不正な応答のテストを追加してください。
使用した公式の出典、モデル名、質問定義の版を記録してください。
実APIで検証したことと、未検証のことを分けて報告してください。
```

## スキルがあっても、正しさを確認する
スキルは、実装時に参照する情報を増やす仕組みです。生成されたコードの品質や、日本語の判定精度を自動で保証するものとしては扱いません。既存のテスト、コードレビュー、評価データでの確認を残します。

:::answer 確認問題：公式スキルを入れたら、APIの更新を自動で必ず追従できますか？
更新方法やエージェントの設定によります。導入した版と、参照した公式資料の確認日を管理し、仕様変更時にテストと評価を行います。
:::
